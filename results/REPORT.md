# Causal Token Network（CTN）第一、第二阶段试验报告

## 1. 范围和结论摘要

本报告按 `ai问答/chatgptV4.md` 第一阶段任务和 `ai问答/chatgptV5.md` 的研究里程碑一、二整理。第一阶段数据/模拟基础和第二阶段首轮学习、泛化实验均已落地。全部结果由本仓库脚本生成，可按 README 命令复跑。

本轮结果**没有显示完整 XYCS 在总体点估计上胜过简单 XY**。XYC 的配对反事实方向准确率与 XYCS 同为 100%，XYCS 的长链深度 5 MSE 低于 XY，但模型间的总体测试 MSE、随机种子方差和领域误差仍存在差距。结论是：当前实现可以验证研究流程、暴露泛化短板；数据规模和模拟规则不足以支持“CTN 优于 Transformer”或现实因果发现的主张。

## 2. 第一阶段：数据结构与模拟世界

### 2.1 实现内容

- 统一 `EventTemplate`、`EventInstance`、`WorldState`、`CausalRelation`、`CausalSample` 结构和 JSON Schema。
- 保留原始 X/Y/C/S 特征，分别提供确定性 32 维编码器；编码器是接口基线，原始字段仍为数据真值。
- 三个可 reset、step、observe、intervene 的环境：温度/物态、一维运动、天气/地面湿度。
- 每个领域 10 个事件模板，共 30 个；因果图含 CAUSE、ENABLE、PREVENT、CORRELATE、TEMPORAL 五类关系。
- 生成器固定随机种子，严格生成事实/反事实二元组：同一 pair 复用初始状态及外生参数，只改变一个指定干预项。
- 训练/验证/测试记录数为 5,000/1,000/1,000；每个 split 的所有记录都属于完整配对，不允许奇数记录数。
- 测试集保留未见组合：mechanics 的 force/friction，thermal 的起始温度，weather 的 rainfall/drainage。
- 生成质量报告，按领域和 split 汇总样本、模板数、图边、事件类型、X/C 组合、关系标签、干预数和配对数。

### 2.2 简化模拟规则

- Thermal：温度按 `T[t+1]=T[t]+10×(heating-cooling)×dt` 更新；`T<=0` 视为 ice，否则为 liquid。
- Mechanics：`a=(force-friction×velocity)/mass`，再更新速度和位置；fixed 会阻止位移。
- Weather：`wetness[t+1]=clip(wetness[t]+rainfall×(1-roof_cover)-drainage, 0, 1)`。

这些是确定性教学模拟规则，省略现实中的潜热、压力、复杂摩擦和水文过程。

### 2.3 数据质量

默认生成器产生 7,000 条记录、3,500 个配对场景和 3,500 条干预记录。各 split 都能通过 Pydantic 重新读取；测试会检查模板/因果边结构、固定物体、遮雨、冻结、随机种子、配对初态和留出组合。

## 3. 第二阶段：模型比较与泛化实验

### 3.1 模型与公平性控制

| 模型 | 可见输入 | 用途 |
|---|---|---|
| XY | X、领域标识 | X→Y 基线 |
| XYC | X、C、领域标识 | 去掉 S 的消融 |
| XYS | X、S、领域标识 | 去掉 C 的消融 |
| XYCS | X、C、S、领域标识 | 完整 CTN 输入结构 |
| Transformer | X/C/S 字段 token、领域标识 | 通用注意力基线 |

Y 仅作为监督目标，不进入推理输入。参数量约为 17,985–22,657（Transformer 19,297），控制在相近规模。XY 的输入信息少于其他完整输入模型，这是明确的特征消融，不把其结果解释成同输入架构竞赛。所有模型使用同一 JSONL 划分、同一连续目标、相同 batch size/学习率/epoch 数。

### 3.2 训练设置

- CPU PyTorch；AdamW，学习率 0.001，batch size 64，20 epochs。
- 随机种子 11、23、37；训练数据固定种子 42。
- 每次实验保存参数量、最终训练损失、验证 MSE/MAE、测试 MSE/MAE、误差容差准确率、分领域误差、配对反事实指标、长链指标、训练/推理耗时。
- 结果文件含数据 SHA-256：`3f8b443eecc6eafb6b4f81da2a79c917b1e83ce2279e65e78dbccd263a1e758b`。

### 3.3 留出组合测试结果

下表为 3 个种子的均值；测试 MSE 和配对 MSE 越低越好，方向准确率越高越好。

| 模型 | 测试 MSE（均值±标准差） | 配对反事实 MSE | 反事实方向准确率 | 参数量 | 长链深度 5 MSE |
|---|---:|---:|---:|---:|---:|
| XY | 0.02192 ± 0.00084 | 0.05408 | 66.8% | 18,177 | 0.11318 |
| XYC | **0.02147 ± 0.00543** | **0.01271** | 100% | 17,985 | 0.11409 |
| XYS | 0.03740 ± 0.00858 | 0.08547 | 66.8% | 17,985 | 0.07236 |
| XYCS | 0.03216 ± 0.00419 | 0.04386 | 100% | 22,657 | **0.08417** |
| Transformer | 0.04400 ± 0.00793 | 0.01438 | 100% | 19,297 | 0.10667 |

完整逐种子、分领域、各深度指标见 `experiment.json`。

### 3.4 长因果链与反事实评估

长链评估从模拟器滚动产生 thermal、mechanics、weather 状态序列，每条轨迹 5 步；模型在各深度接收该深度的当前状态并预测下一步变化。总体上误差随深度增加，符合状态逐渐离开训练分布的预期。此项是“真实模拟状态条件下的逐步预测”，不是模型自由运行的闭环 rollout，后续研究应补做闭环预测误差。

反事实指标按相同 `pair_id` 比较 factual/counterfactual 输出，计算差值 MSE 与变化方向准确率。完整模型和 XYC 的方向准确率为 100%，但预测幅度误差不为零；方向准确率也受本轮干预设计较简单的限制。

## 4. 测试与复现

`pytest`：9 项测试全部通过。包括事件/编码、三模拟规则、固定种子、JSONL 读取、配对状态一致、未见组合、30 个模板及五类因果关系验证。

在安装了 Python 3.11、PyTorch 和项目依赖的环境运行：

```powershell
python -m ctn.cli --output data/generated --seed 42
pytest
python -m ctn.experiment_cli --data data/generated --output results --epochs 20 --seeds 11 23 37
```

运行基准：本地 Windows CPU。V5 建议的 16 vCPU/32GB 服务器并非本轮使用环境，因此训练时间只代表本机，不用于服务器性能推断。

## 5. 限制与下一步

1. 模拟器每个领域当前只生成一种主要监督目标事件，虽然模板库有 30 种模板；事件组合泛化仍较窄。
2. 结果依赖手工指定的模拟方程，不能证明模型能从自然语言发现因果关系。
3. Transformer 在小数据下方差偏大；需要扩大数据规模、调参预算，并做更多随机种子和配对统计区间。
4. XYCS 的参数量仍比其他模型高约 17%–26%；可进一步做更严格的参数量/算力匹配。
5. 下一步应扩展到 50k 数据和多事件机制组合，加入闭环反事实 rollout、置信区间/显著性分析，再评估是否进入自然语言阶段。
