# CTN 第二阶段：因果机制审计与实验诊断

审计范围：当前仓库的数据与模拟器版本；未改动 XY、XYCS、Transformer 的模型架构，未把测试集用于训练，也未将模拟器公式作为模型输入。审计用固定随机种子 11/23/37，训练集拟合、验证集逐 epoch 诊断；独立的配对干预场景只用于预测评估。

## 结论摘要

**当前模拟器有真实的程序内干预机制，但三个领域的训练目标并未让 X/C/S 都同等地参与结果。**机械摩擦、质量、速度和外力确实改变位移增量；热学 C 字段 `freezing_point` 没有接入模拟计算，而训练目标 `temperature_delta` 只由加热/冷却 X 决定；天气的降雨、遮挡、排水参与湿度增量，初始湿度 S 只有在上下界裁剪时才影响增量。

测试数据没有发现重复样本、跨 split 的样本 ID/pair ID 或 X/C/S 完全重叠。发现了**机制短路**（thermal 的 X 直接唯一决定目标）、恒定字段、目标尺度不平衡和编码器/实验向量化不一致。它们不是 train/test 泄漏，但足以解释 XY 的优势并削弱本轮关于 CTN 结构的结论。

## 1. 模拟机制逐领域审计

特征干预直接调用现有 `reset()` / `step()`，固定其余输入。总计 16 个单特征测试，13 个按预期改变所选 Y，3 个按预期不改变 Y，所有预期判断均通过。逐项输入、结果和变化量见 `feature_intervention.json`。

| 世界 | X 影响 | C 影响 | S 影响 | 当前无效/条件性特征 |
|---|---|---|---|---|
| Mechanics | `force` 影响位移增量 | `friction`、`fixed` 影响位移增量 | `mass`、`velocity` 影响；`position` 不影响位移增量 | 生成数据中的 `fixed` 恒为 false；位置平移不影响位移增量 |
| Thermal | heating/cooling 改变温度增量 | `freezing_point` 不影响，因为代码在 0°C 硬编码阈值 | 起始温度可改变相态；对温度增量没有影响 | 输入 phase 会被按温度重算；训练目标没有相态标签，故对当前 Y 无效 |
| Weather | `rainfall` 改变湿度增量 | `roof_cover`、`drainage` 改变湿度增量 | `ground_wetness` 在裁剪边界附近改变增量 | 在未触及上下界时，改变初始湿度不会改变本步增量 |

不同输入产生同一 Y 是当前机制的必然情况：例如固定加热功率时，不同初始温度会有相同 `temperature_delta`；机械位置整体平移不改变位移增量；无雨且未触及裁剪边界时，遮挡变化没有影响。天气裁剪也会让多组不同输入映射到相同的 0 或 1 湿度。

## 2. 数据质量、泄漏与目标捷径

机器可读统计见 `data_quality.json`。当前默认数据为 5,000/1,000/1,000 条，所有记录均成事实/反事实对；没有 split 内重复，没有跨 split 重复记录、样本 ID、pair ID 或完全相同的 X/C/S 组合。三个 split 使用独立场景编号和独立外生随机数；测试条件组合与训练条件组合不相交。

目标统计来自训练集，模型接收的实际目标按当前训练代码缩放：

| 领域 | 原始 Y 范围 | 模型目标范围 | 模型目标标准差 | IQR 异常数 |
|---|---:|---:|---:|---:|
| Thermal 温度增量 | -10 到 10 | -1 到 1（除以 10） | 1.000 | 0 |
| Mechanics 位移增量 | -0.499 到 3.498 | -0.0499 到 0.3498（除以 10） | 0.103 | 59 |
| Weather 湿度增量 | -0.1 到 0.2 | -0.1 到 0.2（未缩放） | 0.097 | 0 |

Mechanics 的 59 个 1.5×IQR 点是合法模拟尾部样本，不是非有限值或损坏记录；仍需在报告指标中保留而不能静默剔除。当前是“按领域乘固定比例”，不是按领域标准化；汇总 MSE 的 thermal 误差权重大约比另外两领域高两个数量级。X/C/S 输入也没有归一化。

没有发现 Y、`target_state`、`state_after`、sample ID 或 pair ID 被传入模型。`_read()` 只取 X/C/S 数值投影和领域标识，因此不存在把真实 Y 作为输入的直接答案泄漏。但存在机制捷径：thermal `Y=10×(heating-cooling)`，所以 X 单独就精确确定当前标量目标；C 和 S 对这个标签没有因果影响。XY 在这一领域不需要学习任何条件机制。

存在数据生成/编码表示不一致：文档声明的 32 维独立哈希编码器没有被实验调用；训练实际使用 `_vec()`，只保留排序后的前 8 个数值/布尔值，并将字符串类别写成 0。`mechanics X.action` 和 `thermal S.phase` 因此被丢弃。训练统计中的常量还包括 mechanics `C.fixed=false`、`S.fixed=false` 和 thermal `C.freezing_point=0`。

## 3. 严格配对反事实预测

每种干预建立 80 对，共每个模型/领域跨 3 个种子评估 240 个配对预测：

- Mechanics：初始位置、速度、质量和外力固定，只改变摩擦系数。
- Thermal：加热/冷却和其他条件固定，只将初始温度从 -2°C 改为 2°C。相态跨越冻结点，但当前被预测的温度增量应保持不变。
- Weather：初始湿度、遮挡和排水固定，只改变降雨量。

指标定义和每一对的输入、预测、单样本误差、变化幅度误差见 `counterfactual_pairs.json`。方向准确率不对真实变化为零的 thermal 温度增量计算；该处单独报告零效应保持率。

| 模型 | Mechanics 方向准确率 / 变化误差 | Thermal 零效应保持率 / 变化误差 | Weather 方向准确率 / 变化误差 |
|---|---:|---:|---:|
| XY | 0% / 0.0350 | 100% / 0.0000 | 100% / 0.3403 |
| XYCS | 100% / 0.0456 | 0% / 0.0357 | 100% / 0.2436 |
| Transformer | 100% / 0.0101 | 0% / 0.0362 | 0% / 0.8624 |

误差使用各领域训练时的目标尺度。XY 不接收 C，所以不能预测只改变 friction 引起的变化；但它在这些 friction 反事实对的基准误差仍较小，反映模型靠近训练分布的平均关系可得到低误差，却没有学到干预响应。Thermal 的任务定义存在更根本的问题：改变温度会翻转 phase，但被训练模型预测的是温度增量而非相态，因而这组模型无法回答相态反事实问题。

## 4. 训练诊断（XY、XYCS、Transformer）

逐 epoch 训练和验证 MSE、每次运行的最佳 epoch、梯度检查和随机种子结果均见 `training_diagnostics.json`。架构未改动，参数量/输入字段如下：

| 模型 | 实际输入 | 参数量 | 最佳 epoch（种子 11/23/37） | 末轮过拟合运行 | 非有限梯度 |
|---|---|---:|---|---:|---:|
| XY | X、domain | 18,177 | 16 / 17 / 20 | 1/3 | 0 |
| XYCS | X、C、S、domain | 22,657 | 18 / 19 / 16 | 3/3 | 0 |
| Transformer | X/C/S 字段 token、domain | 19,297 | 19 / 17 / 16 | 3/3 | 0 |

过拟合定义：末轮验证 MSE 比该运行最佳验证 MSE 高至少 5%。测试集仅在完整训练完成后作一次评估。三个种子的测试 MSE 均值±样本标准差：XY `0.02192±0.00084`，XYCS `0.03216±0.00419`，Transformer `0.04400±0.00793`。这和用户任务说明中引用的 `0.00784/0.01595/0.03058` 不同，因为本轮使用的当前数据与实验记录已更新；本轮数据哈希为 `3f8b443eecc6eafb6b4f81da2a79c917b1e83ce2279e65e78dbccd263a1e758b`，不应把两套分数混为同一实验。

**XYCS/Transformer 较差的可验证原因**：三次运行末轮验证误差均回升；它们输入更多但样本仅 5,000 条，并包含未训练的字段；thermal 目标让 X 成为充分统计量；pooled MSE 的跨领域目标尺度不一致；类别字段丢失；此外更大输入模型有更多参数（XYCS 比 XY 多 24.6%）。这些因素共同使当前比较不能单独归因于 CTN 架构。

## 5. 对任务问题的回答

1. **当前模拟器是否有可学习的因果机制？** 有。代码级单特征干预验证了外力、摩擦、质量、速度、遮挡、排水和降雨等真实改变模拟结果。但热学 C 未接入，mechanics fixed 未在训练数据变化，某些 S 特征对监督目标无效。
2. **C 和 S 是否影响 Y？** 视领域和目标定义而定。Mechanics friction 有效、位置无效、fixed 有效但恒定；Thermal freezing_point 无效，起始温度只影响 phase 而不影响训练目标；Weather C 中 roof/drainage 有效，S 在湿度裁剪边界时有效。
3. **XY 为什么更好？** Thermal 的目标由 X 直接计算且占 pooled loss 高权重；额外 C/S 中含常量、目标无关或模型编码器丢失的字段。XY 更小且过拟合较少。低 MSE不等于学到了因果响应，摩擦反事实已经展示这一点。
4. **数据是否足以验证 CTN 理论？** 不足。每个领域仅训练一个主结果事件，规则是手工给定的、参数空间窄，目标是单步标量，样本规模和模型调参预算也小。
5. **下一轮最应该修改什么？** 修正目标/特征契约：把 thermal 相态纳入监督目标；让 freezing threshold 真正作为 C 进入 simulator；在训练中变化 fixed；使用一致、保留类别语义的特征编码；对连续输入和各领域目标分别标准化；加入可控制的 C/S 干预对和无效字段测试。完成这些数据修复后再做匹配参数量的模型实验。
6. **当前不能判断什么？** 无法判断 CTN 是否能从自然语言发现因果、是否优于大型 Transformer、是否学到可迁移因果表示，也不能从本轮小规模试验判断架构本身的因果贡献。

## 6. 复现

在项目目录执行：

```powershell
python -m ctn.audit
```

该命令生成本报告配套 JSON，并以当前 XY/XYCS/Transformer 架构跑 20 epoch、3 个随机种子的训练诊断。测试集不进入梯度更新；如需只重新生成静态机制和数据审计，可调用 `write_audit_reports()`。
